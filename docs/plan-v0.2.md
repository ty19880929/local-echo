## 1. UI 优化

### 1.1 文件卡片操作行（U1）

**现状**：`src/ui/chat.rs:955-986`。卡片完成后，底部操作行有「打开」「打开所在文件夹」两个文字按钮，宽度随内容、靠左排列（设计稿 `LE Window.dc.html:193-196` 也是这样画的）。

**改动**：

- 两个操作都加上 `.flex_1().justify_center()`，各占卡片宽度的一半，文字居中。联系人卡片宽 320，每个操作约 160；服务器卡片宽 340，每个约 170。高度 32、中间的 1px 竖线、链接色和悬停背景都保持不变。
- 「打开所在文件夹」改名为「打开文件夹」。同时更新 `docs/design.md` 4.4 节和附录 A 第七节的文案表。
- 涉及四种卡片：我发出的、对方发来的、上传到服务器的、从服务器下载的。它们走同一段代码，一处改动就能全部覆盖。
- 两个按钮的点击逻辑换成第 3 节新增的 `desktop::open` / `desktop::reveal`，见 B1。
- **文件不存在时给出提示**（已确认 #13）：
  - 现在：传输成功但本地文件已经不在（被移动、改名或删除）时，操作行被静默隐藏。
  - 改为：在操作行的位置显示「文件已被移动或删除」，muted 色、13 px、高 32、带上边框，与操作行等高，卡片高度不跳动。
  - 适用于所有已完成的卡片：收到的、下载的文件，以及我发出的、上传的文件（这两种指向的是原文件，原文件被移走时同样适用）。图片消息的文件丢失时，现在本来就退化为文件卡片显示，也一并适用。
  - 不提供「重新定位文件」之类的功能。

### 1.2 本机 IP 移到设置页（U2）

**现状**：`src/ui/app.rs` 在 `AppView::new` 中读取一次网卡列表（`:48`），由 `render_ips`（`:171`）画在侧边栏顶部（`:429`），点击复制（`copy_ip`，`:120`）。设置页（`src/ui/settings.rs:333-335`）目前有「数据目录」「开机自动启动」「关于」三组。

**改动**：

| 项 | 方案 |
|---|---|
| 侧边栏 | 删除 IP 区块，以及 `AppView` 的 `ips`、`copied`、`copy_ip`、`render_ips`。侧边栏直接从「联系人」分组开始 |
| 设置页位置 | 新增分组「本机 IP」，放在**第一组**（「数据目录」之前）。IP 不在侧边栏后，用户来设置页大多是为了查看它 |
| 表格 | 列：「网卡」「IP 地址」「操作」（复制图标按钮）。IP 用等宽字体。样式沿用远程浏览器的表格（`dialogs.rs:946` 起：`table_head` 表头、`table_row_border` 行线），并把表头和行的样式抽成 `kit` 里的公共函数，两处共用 |
| 收起 / 展开 | 分组标题行右侧放一个 chevron，整行都可以点击。收起时只显示一行摘要，例如「192.168.1.10 等 3 个」，最常用的 IP 不用展开就能看到。默认展开；用户的选择记在 `AppState` 里，只在本次运行期间有效，不写盘（已确认 #1） |
| 复制 | 点击复制图标，或双击 IP 单元格：写入剪贴板，弹出 Toast「已复制 {ip}」，该行图标在 2 秒内显示为对勾（沿用现有行为） |
| 说明 | 卡片底部提示：「联系人添加你时，填写其中任意一个 IP 即可（端口固定为 47210）」 |
| 数据来源 | 把读取网卡的逻辑移到新函数 `net::local_ips()`。每次打开设置页、每次展开时重新读取，网络变化（换 Wi-Fi、连 VPN）后不用重启程序。过滤规则：IPv4、非回环，另外**过滤 169.254.0.0/16**（Windows 上断开的网卡常显示这个自动分配地址，用户填了也连不上，已确认 #8） |
| 空状态 | 「未检测到可用的网络连接」 |

### 1.3 底部分割线对齐（U3）

**现状**：三处底栏都画了上边框，但高度各不相同，所以分割线不在同一水平线上。设计稿本身就是这样画的，代码按设计稿实现：

| 位置 | 代码 | 内容高度 | 与侧边栏的差值 |
|---|---|---|---|
| 侧边栏底部「设置」区 | `app.rs:452`：`p_2` + 36 行高 | 8 + 36 + 8 = **52** | — |
| 联系人输入区（单行时） | `chat.rs:526`：`py_3` + 36 按钮 / 单行输入框 | 12 + 36 + 12 = **60** | 8 |
| 服务器底栏 | `chat.rs:585`：`py_3` + 40 拖拽区 / 按钮 | 12 + 40 + 12 = **64** | 12 |

**改动**：新增常量 `kit::FOOTER_H = 60.`，含义是「不含 1px 上边框的底栏高度」。

- 侧边栏底部：`.h(px(FOOTER_H))`，「设置」行仍为 36，垂直居中，上下各留 12。
- 联系人输入区：`.min_h(px(FOOTER_H))`，单行时正好 60；输入多行时向上增高，这时不要求对齐。gpui-kit `Textarea` 在 Medium 尺寸下的单行高度由内边距、行高和边框共同决定，代码里不好直接算出来。实现时先在 Xvfb 中截图量出实际高度，如果单行不是 36，就调整输入框的内边距，让单行正好 36。
- 服务器底栏：也用 `.h(px(FOOTER_H))`，拖拽区和「上传文件」按钮从 40 改为 36。原需求只提到输入区，但如果服务器底栏不改，切到服务器会话时分割线仍会错开 4px，所以一起改（已确认 #2）。
- 验收方法：浅色和深色主题下各截一张联系人会话、一张服务器会话，比对两侧分割线所在的像素行，必须是同一行。

## 2. 功能扩展：在远程桌面打开（F1）

### 2.1 前提与边界

- **协议**：RDP。`mstsc` 只支持 RDP，Linux 上主流客户端也都支持 RDP，两个平台可以统一。
- **服务器端**：服务器需要自己开启 RDP 服务，例如 Windows 远程桌面、Linux 的 xrdp / GNOME 远程桌面 / KDE KRdp。本工具不负责安装或配置这些服务。
- **地址**：使用该服务器的 SSH 地址（`contact.host`）。端口默认 3389，可以在「编辑服务器」中修改（已确认 #3）。
- **用户名**：默认预填该服务器的 SSH 用户名，用户可以在客户端的登录框里改，不另设字段（已确认 #4）。
- **密码不保存**，与 5.1 节「密码不落盘」的原则保持一致。RDP 无法使用本工具的 SSH 密钥，所以密码由客户端自己询问，记住密码也交给客户端处理：mstsc 的「记住我的凭据」存进 Windows 凭据管理器；Remmina 的「保存密码」存进系统钥匙环。
- **与 SSH 密钥无关**：密钥失效不影响远程桌面，「重新授权」横幅也不影响这个按钮。

### 2.2 交互流程

```
点击「在远程桌面打开」
  → 按钮进入「正在连接…」状态（Spinner，不可重复点击）
  → TCP 探测 host:rdp_port，最多 3 秒（tokio，与联系人连接的超时一致）
      ├─ 失败 → Toast：无法连接 {host}:{port}：服务器未开启远程桌面，或端口不可达。可在「编辑服务器」中修改远程桌面端口
      └─ 成功 → 拉起本机客户端（2.3 / 2.4）
             ├─ 拉起失败或找不到客户端 → Windows：Toast 显示原因；Linux：对话框「未找到远程桌面客户端」+ 安装命令
             └─ 成功 → 按钮恢复常规状态（不弹成功提示，客户端窗口本身就是反馈）
```

先做端口探测，是因为客户端拉起后的失败提示五花八门，有的还要等很久才超时。在本工具里先探测一次，「服务器没开远程桌面」这种最常见的错误就能当场用中文说清楚。

### 2.3 Windows：mstsc

所有 Windows 版本都自带 `mstsc.exe`。家庭版不能被远程连接，但客户端可以用。

- 不用 `mstsc /v:host:port`，因为这种方式不能预填用户名。改为每次生成一个 `.rdp` 文件，再执行 `mstsc <文件>`：
  - 路径：`%TEMP%\local-echo\rdp-<contact_id>.rdp`，每次覆盖写入。文件里**不含密码**。
  - 编码：与 mstsc 自己保存 `.rdp` 文件的格式一致，用 UTF-16LE 带 BOM，这样用户名里有中文也不会乱码。
  - 内容：只写两行，其余设置（全屏、分辨率、证书提示等）都用 mstsc 的默认值：
    ```
    full address:s:<host>:<rdp_port>
    username:s:<user>
    ```
- mstsc 的凭据对话框会预填用户名，用户输入密码后可以勾选「记住我」。
- 证书不受信任时，mstsc 会弹出警告，警告里有「不再询问」。这里保持 mstsc 的默认行为，不写 `authentication level:i:0` 去关掉警告。
- 不用 `cmdkey` 预存凭据，因为需要密码，而本工具不保存密码。

### 2.4 Linux：调研与方案

**调研方法**（2026-11-10）：在 Ubuntu 26.04 上用 `apt-get download` 下载各客户端的软件包，检查可执行文件名、`.desktop` 文件注册的 MIME 类型、`--help` 文本和二进制中的符号。没有实际连接 RDP 服务器，实际连接的验证见 2.8 节。

| 客户端 | 软件包 / 可执行文件 | 拉起命令 | 凭据输入 | 依据 | 结论 |
|---|---|---|---|---|---|
| **Remmina** 1.4.43 | `remmina` + `remmina-plugin-rdp` / `remmina` | `remmina -c rdp://<user>@<host>:<port>` | 图形登录框，可以保存密码到钥匙环（`remmina-plugin-secret`） | `--help` 原文：`remmina -c rdp://username@server`；`remmina` 把 RDP 插件列为 Recommends；`ubuntu-desktop` 和 `ubuntu-desktop-minimal` 都推荐安装 `remmina`，**Ubuntu 桌面版默认自带** | **首选** |
| Remmina（Flatpak） | `org.remmina.Remmina` | `flatpak run org.remmina.Remmina -c rdp://…` | 同上 | 通过 Flathub 安装时不在 PATH 中，需要单独探测（`flatpak info org.remmina.Remmina`） | 首选的补充 |
| **KRDC** 25.12 | `krdc` / `krdc` | `krdc rdp://<user>@<host>:<port>` | 图形 | `.desktop`：`Exec=… %u`，注册了 `x-scheme-handler/rdp` | 次选（KDE） |
| **FreeRDP 3 SDL 客户端** 3.32 | 26.04：`freerdp-sdl` / `sdl-freerdp`（过渡包 `freerdp3-sdl` 提供 `sdl-freerdp3` 链接）；24.04：`freerdp3-sdl` / `sdl-freerdp3` | `sdl-freerdp3 /v:<host>:<port> /u:<user> /t:<服务器名称> /dynamic-resolution +clipboard` | SDL 自带凭据对话框和证书对话框 | 二进制中有 `sdl_auth_dialog_show`、`sdl_cert_dialog_show` | 备选。可执行文件名两种都探测，先 `sdl-freerdp3`，再 `sdl-freerdp` |
| FreeRDP X11 客户端 | `xfreerdp3` / `xfreerdp` | — | 只能在终端里输入凭据 | 从图形程序拉起时没有终端可以输入密码；22.04 / 24.04 的 `xfreerdp` 还是 FreeRDP 2 | **不采用** |
| GNOME Connections 49 | `gnome-connections` | `gnome-connections rdp://<host>:<port>` | 图形 | 程序有命令行入口（`connections_application_real_command_line`，只接受 1 个参数），内部支持 `rdp://`；但 `.desktop` 只注册了 `application/x-vnc`，**从命令行传入 `rdp://` 能否直接连接需要实测** | 实测通过后才加入（Fedora Workstation 默认自带） |
| 系统默认处理程序 | `xdg-mime query default x-scheme-handler/rdp` 有结果时 | `xdg-open rdp://<user>@<host>:<port>` | 取决于具体程序 | 覆盖上面没有列出、但注册了 `rdp://` 的客户端 | 兜底 |

**探测顺序**：Remmina → Flatpak Remmina → KRDC → `sdl-freerdp3` / `sdl-freerdp` → GNOME Connections（实测通过后）→ 系统默认的 `rdp://` 处理程序 → 都没有时弹出对话框。探测方式沿用 `host.rs` 中的 `which()`，在 PATH 中查找。

为什么不把「系统默认处理程序」放在第一位：Remmina 注册的处理程序是 `remmina-file-wrapper %U`，它执行的是不带 `-c` 的 `remmina rdp://…`。直接调用 `remmina -c` 行为更确定，所以默认处理程序只作兜底。

**URI 规则**：`rdp://<user>@<host>:<port>`。主机是 IPv6 地址时加方括号。用户名含有 `@ : / ? # %` 时省略用户名部分，由客户端询问，避免各客户端解码方式不同导致登录用户错误。

**找不到客户端时的对话框**：

| | 内容 |
|---|---|
| 标题 | 未找到远程桌面客户端 |
| 说明 | 需要安装一个支持 RDP 的远程桌面客户端，推荐 Remmina。 |
| 命令（等宽字体，每行都可以复制） | Ubuntu / Debian：`sudo apt install remmina remmina-plugin-rdp`<br>Fedora：`sudo dnf install remmina remmina-plugins-rdp`<br>Flatpak：`flatpak install flathub org.remmina.Remmina` |
| 按钮 | 知道了 |

只给安装提示，不退回到「在终端里运行 xfreerdp」（已确认 #5）。

### 2.7 打包

- deb：在 `[package.metadata.deb]` 中加 `suggests = "remmina, remmina-plugin-rdp | krdc | freerdp3-sdl"`；rpm：在 `[package.metadata.generate-rpm.suggests]` 中加 `remmina = "*"`。
- 只用 Suggests，不用 Recommends。Recommends 在 apt 下默认会被安装，会给每个用户都装上 Remmina 及其 GTK 依赖，违背「极致轻量」的定位（已确认 #6）。
- Windows 安装包不需要改动。

### 2.8 风险与验证

| # | 风险 | 对策 |
|---|---|---|
| R11 | 服务器没有开启 RDP 服务 | 2.2 的端口探测会给出明确提示；在 README 中说明服务器端的前提 |

## 3. 修复：Windows 下「打开所在文件夹」没有反应（B1）

### 3.1 现象

Windows 上，点击联系人发来的文件卡片中的「打开所在文件夹」，既没有打开资源管理器，也没有任何提示。

### 3.2 根因（2026-11-11 已在 Windows 测试机上复现并确认，见 3.2.1）

1. 收到的文件在库里存的是相对路径，`to_stored`（`src/data.rs:144`）会把 `\` 统一替换成 `/`，所以存下来的是 `files/报告.pdf`。
2. 显示时，`resolve_stored`（`src/data.rs:151`）执行 `root.join("files/报告.pdf")`。在 Windows 上得到的是**混用分隔符**的路径：`C:\Users\…\local-echo\files/报告.pdf`。
3. 按钮调用的是 `cx.reveal_path`（`src/ui/chat.rs:983`）。gpui-pre-windows 0.3.12 中，它最终调用 `open_target_in_explorer`（`platform.rs:1543`）：先用 `IShellFolder::ParseDisplayName` 把文件路径解析成 Shell 对象，再调用 `SHOpenFolderAndSelectItems`。Shell 的路径解析不把 `/` 当作分隔符，所以解析失败。降级逻辑只处理 `SHOpenFolderAndSelectItems` 返回的 `ERROR_FILE_NOT_FOUND`，其他错误一律经 `log_err()` 写进日志就结束了。结果就是**没有任何反馈**。
4. 旁证一：「打开」走的是 `ShellExecuteW`，它能接受 `/`，所以同一张卡片上「打开」可以用。旁证二：我发出的文件存的是文件对话框返回的绝对路径，全部是 `\`，不受影响。

从服务器下载的文件也存相对路径，同样会出现这个问题。

#### 3.2.1 复现记录（2026-11-11，Windows 测试机，交叉编译的 v0.1.0）

| 步骤 | 结果 |
|---|---|
| 在测试数据副本中，点击一个收到的文件卡片上的「打开所在文件夹」 | 没有任何反应。点击前后用 `Shell.Application` 列出资源管理器窗口，前后完全相同，没有打开任何新窗口 |
| 对同一个文件调用 `SHParseDisplayName`，路径为 `…\le-test\data\files/Platform_….docx`（混用 `/`） | 失败，`0x80070057`（E_INVALIDARG，参数错误） |
| 同一个文件，路径全部用 `\` | 成功 |
| .NET 判断上面那个混用 `/` 的路径是否存在 | 存在 |

结论：Shell 的路径解析不接受 `/`，gpui 把这个错误吞掉了。3.3 节的修复方法有效。

**顺带发现**：你测试机上收到的两个文件已被改名（`Platform_construction_progress_report.*` → `平台汇报_2026111x.*`）。记录指向的文件不存在了，所以卡片上的操作行被**静默隐藏**，界面上看不出原因，见 6.3 #13。

### 3.3 修复

| 改动 | 说明 |
|---|---|
| `data::resolve_stored` 统一分隔符 | 相对路径按 `/` 切开后逐段 `push`，得到全部使用本机分隔符的路径。这一步同时修好图片的「用系统查看器打开」和文件的「打开」所用的路径 |
| 新增 `desktop::reveal(path) -> Result<()>` | 先检查文件是否存在，不存在时返回「文件不存在，可能已被移动或删除」。Windows：`explorer.exe` 加 `raw_arg(format!("/select,\"{}\"", path.display()))`。用 `CommandExt::raw_arg` 是因为 explorer 解析参数的方式不标准，路径里有空格时自动加的引号会出问题。explorer 成功时也会返回退出码 1，所以只把「进程启动失败」当作错误。Linux：继续使用 `cx.reveal_path`，试用时表现正常 |
| 新增 `desktop::open(path) -> Result<()>` | 先检查文件是否存在，再调用 `cx.open_with_system` |
| 界面反馈 | 卡片的「打开」「打开文件夹」和图片点击都改用上面两个函数，出错时弹出错误 Toast：「无法打开文件夹：{原因}」或「文件不存在，可能已被移动或删除」 |
| 测试 | `resolve_stored` 增加单元测试：Windows 下断言结果不含 `/`，所有平台都断言与逐段拼接的结果相等。Windows 专用的断言在 Windows 测试机上运行（见 5.1） |

### 3.4 Windows 验收清单

- 收到的文件、从服务器下载的文件、我发出的文件：「打开文件夹」都能打开资源管理器，并选中这个文件。
- 路径中有空格和中文时（例如数据目录迁移到 `D:\我的 文件\echo`）同样正常。
- 在资源管理器中手动改名或删除文件后：卡片的操作行换成「文件已被移动或删除」（#13）。如果在点击前一刻才删除，会弹出「文件不存在」的提示。

| 问题 | 解决方法 |
|---|---|
| **着色器**：gpui 的 Windows 正式构建在 `build.rs` 中调用 Windows SDK 的 `fxc.exe` 编译 HLSL 着色器，而且只在编译机本身是 Windows 时才执行。交叉编译时这一步被跳过，编译到 `include!(OUT_DIR/shaders_bytes.rs)` 时报错，这是唯一的编译错误 | 用测试机系统自带的 `d3dcompiler_47.dll`（`fxc.exe` 内部用的就是它）把 16 段着色器预编译一次，编译参数与 `build.rs` 中的 `/O3` 一致，生成格式相同的 `shaders_bytes.rs`。这一步只是在临时目录里运行一个 PowerShell 脚本，不在测试机上安装任何东西，跑完就删掉。生成结果和脚本放进仓库的 `packaging/windows/cross/`。gpui 固定在 0.3.12，着色器不变，就不用重新生成。构建脚本 `scripts/build-windows.sh` 负责把这个文件放进 gpui-pre-windows 的 `OUT_DIR`，再完成构建 |

- **图形界面操作**：用计划任务（`schtasks … /it`）在会话 2 中启动程序、运行截图脚本、模拟点击，截图拷回本机核对。由我远程操作，每次开始前先征得你同意（已确认 #12）。

# 修改 1：文件卡片操作行（含「文件已不存在」状态）

**现状**：文件传输完成后，卡片底部有一行操作「打开」「打开所在文件夹」：两个文字按钮按内容宽度靠左排列，高 32，中间有 1 px 竖线，链接色，13 px / 600。

**要求**：
- 两个按钮**均分卡片整宽**（各占 50%），文字水平居中；1 px 竖线、高度 32、链接色、字号不变。
- 「打开所在文件夹」改名为 **「打开文件夹」**。
- 悬停：所在的那一半整块显示 muted 背景。
- 联系人卡片宽 320，服务器卡片宽 340（服务器卡片多一行远端路径），两种宽度都要更新。我发出的、对方发来的、上传、下载四种卡片的「已完成」状态都要更新。
- **新增状态「文件已不存在」**：传输成功，但本地文件后来被移动、改名或删除。现在这种情况下操作行被直接隐藏，用户看不出原因。改为在操作行的位置显示一行提示「文件已被移动或删除」：
  - muted 色，13 px，左对齐，内边距与操作行一致；
  - 高 32，保留上边框，与操作行等高，卡片高度不变；
  - 不可点击，不提供「重新定位文件」之类的操作。
  请画出联系人卡片和服务器卡片各一例。

# 修改 2：「本机 IP」从侧边栏移到设置页

**现状**：侧边栏顶部显示「本机 IP：192.168.1.10」，有多个 IP 时列出「本机 IP（点击复制）」+ 每行「IP + 网卡名 + 复制图标」。设置页（显示在右侧会话区，最大宽度 640）目前有「数据目录」「开机自动启动」「关于」三个分组，每组是「标题 14/600 + 卡片（popover 底、1 px 边框、内边距 16）」，页面最下方是「退出 Local Echo」。

**要求**：
1. **侧边栏**：删除顶部的本机 IP 区块，侧边栏从「联系人」分组开始。请检查删除后侧边栏顶部的留白是否合适。
2. **设置页**新增分组 **「本机 IP」**，放在第一组（「数据目录」之前）。
3. 分组内用 **Table** 展示，列为「网卡」「IP 地址」「操作」：
   - 「IP 地址」用等宽字体；「操作」列是复制图标按钮（Lucide `copy`），点击后该行图标在 2 秒内变成对勾（`check`，success 色），同时弹出 Toast「已复制 192.168.1.10」。
   - 表头、行高、行线沿用第一版「远程目录浏览器」的表格规格。
   - 网卡名可能很长，例如 `vEthernet (WSL (Hyper-V firewall))`、`enp0s31f6`、`docker0`，需要中间省略或截断。
4. **支持收起 / 展开**：
   - 分组标题行右侧放 chevron（Lucide `chevron-down` / `chevron-right`），整行都可以点击。
   - 收起时，卡片内只显示一行摘要，例如「192.168.1.10 等 3 个」，最常用的 IP 不展开也能看到；只有 1 个 IP 时直接显示这个 IP。
   - 默认展开。
   - 请画出展开、收起两种状态，并标注可点击区域和悬停态。
5. 卡片底部的说明（muted 色）：「联系人添加你时，填写其中任意一个 IP 即可（端口固定为 47210）」。
6. 需要画出的状态：1 个 IP；3–4 个 IP（含长网卡名）；未检测到网络（「未检测到可用的网络连接」）；刚复制某个 IP。

# 修改 3：左右两侧底部分割线对齐

**现状**：三处底栏的上边框不在同一水平线上：
- 侧边栏底部的「设置」区：高 52（上下内边距 8 + 36 行高）；
- 联系人会话的输入区（单行时）：高 60（上下内边距 12 + 36）；
- 服务器会话的底栏：高 64（上下内边距 12 + 40 高的拖拽区和按钮）。

**要求**：
- 定义统一的 **底栏高度 token = 60**（不含 1 px 上边框）。
- 侧边栏底部「设置」区：高 60，「设置」行仍为 36，垂直居中。
- 联系人输入区：单行时高 60；输入多行时向上增高（最多约 6 行），这时不要求对齐。
- 服务器底栏：高 60，虚线拖拽区和「上传文件」按钮都改为高 36。
- 在 1000×680 的联系人会话和服务器会话画布上各标出一条对齐参考线，证明左右两侧的分割线在同一像素行。

# 修改 4：服务器会话新增「在远程桌面打开」

**功能**：用本机的远程桌面客户端（Windows：系统自带的「远程桌面连接」mstsc；Linux：Remmina 等）以 RDP 协议连接这台服务器。
- 用户名默认使用该服务器的 SSH 用户名；**密码由远程桌面客户端自己询问，Local Echo 不保存**。
- 点击后先检测服务器的远程桌面端口（默认 3389）能否连通，最多 3 秒，再拉起客户端。

**要求**：

a) **会话头部的操作按钮**：现在头部右侧有两个次要按钮「下载文件」（`download`）「在终端中打开」（`square-terminal`）。新增 **「在远程桌面打开」**，图标从 Lucide `monitor` 和 `screen-share` 中选一个，并说明理由。
   - 会话区宽度：窗口最小时为 500（760 − 260），默认 740。三个带文字的按钮约需 400 px，会话区为 500 时放不下，还会挤压左侧的服务器名称和远程目录。
   - 请给出窄宽度方案（例如会话区小于某个宽度时，「在终端中打开」「在远程桌面打开」收成 36×36 的图标按钮并加 Tooltip；你也可以提出更好的方式，但不要把常用操作藏进二级菜单），写明切换阈值，并画出会话区 740 和 500 两种宽度。
   - 按钮状态：常规、悬停、**检测中**（按钮内显示 Spinner，文字为「正在连接…」，期间不能再次点击）。
   - 确认头部同时出现「密钥失效横幅」时布局正常（横幅在头部下方，与这个按钮互不影响）。

b) **失败反馈**：
   - 错误 Toast：「无法连接 192.168.1.20:3389：服务器未开启远程桌面，或端口不可达。可在「编辑服务器」中修改远程桌面端口」（文字较长，请确认 Toast 的换行和最大宽度）。
   - 错误 Toast：「无法启动远程桌面客户端：{原因}」。
   - 对话框「未找到远程桌面客户端」（只在 Linux 上出现）：
     - 说明：「需要安装一个支持 RDP 的远程桌面客户端，推荐 Remmina。」
     - 三行安装命令，等宽字体，每行右侧有复制图标按钮：
       `Ubuntu / Debian：sudo apt install remmina remmina-plugin-rdp`
       `Fedora：sudo dnf install remmina remmina-plugins-rdp`
       `Flatpak：flatpak install flathub org.remmina.Remmina`
     - 按钮：「知道了」。

c) **编辑服务器对话框**：在「用户名」之后新增字段 **「远程桌面端口」**：选填，占位 `3389`，只能输入 1–65535；字段下方提示「用于“在远程桌面打开”，默认 3389」；错误态文案「请输入 1–65535 之间的端口」。「添加服务器」和「重新授权」对话框**不变**。

# 实现约束（与第一版相同）

1. 只能使用 gpui-kit 已有的组件形态：TitleBar、Sidebar、Avatar、Badge、Button（primary / secondary / ghost / link / danger，支持 loading）、Input、Textarea、Switch、Dialog、Popover、Tooltip、Notification（Toast）、Alert、Progress、Spinner、**Table**、List、**Collapsible / Accordion**、Setting、Message / Bubble、Attachment、MessageScroller。
2. 图标只用 Lucide。
3. 4 px 栅格；只用纯色和 1 px 细边框；阴影只用于浮层；不用毛玻璃和渐变。
4. 浅色、深色两套都要画；适配 1× 和 2× 缩放；中文文本按比英文长 30% 留余量。
5. 动效克制，只用于悬停、按下、浮层出现、展开 / 收起，时长不超过 150 ms。
